# Project Memory — Keputusan Arsitektur

## Autentikasi (PENTING — jangan diubah)
- Login memakai tabel kustom **`admins`** (`username` + `password_hash` bcrypt) — **BUKAN** `auth.users` Supabase Auth.
- **Alasan:** project ini harus portabel dari Supabase ke Laragon/MySQL. Jangan pernah memigrasi ke Supabase Auth / `auth.users`.
- Skema lengkap: `schema.supabase.sql` (PostgreSQL / Supabase) dan `schema.mysql.sql` (MySQL / Laragon).
- **KONVENSI**: setiap perubahan di `schema.mysql.sql` WAJIB diterapkan juga ke `schema.supabase.sql` — alur & struktur tabel sama persis, hanya syntax disesuaikan per DB (AUTO_INCREMENT vs SERIAL, TIMESTAMP vs TIMESTAMPTZ, dll). **Tanpa `auth.users()`** di kedua file.
- **Migrasi**: folder `migrations/` berisi file SQL berpasangan `supabase/<NN>_*.sql` dan `mysql/<NN>_*.sql` dengan alur sama persis (konvensi yang sama seperti schema). Migrasi bersifat idempotent (ON CONFLICT DO NOTHING / ON DUPLICATE KEY UPDATE no-op) dan dijalankan SETELAH schema. Contoh: `migrations/supabase/01_seed_dummy_data.sql` ↔ `migrations/mysql/01_seed_dummy_data.sql` berisi seed lengkap 17 app + 51 tech + 16 kategori.
- **⚠️ Gotcha sequence id**: seed memakai id EKSPLISIT (1-17) yang TIDAK menggerakkan sequence (PostgreSQL) / AUTO_INCREMENT (MySQL). Tanpa sinkronisasi, INSERT baru menabrak id lama → error 500 `duplicate key value violates unique constraint "apps_pkey"`. Selalu sertakan `setval(...)` (Supabase) / `ALTER TABLE ... AUTO_INCREMENT = MAX(id)+1` (MySQL) di akhir migrasi apa pun yang memasukkan baris dengan id eksplisit. Perbaikan untuk DB yang sudah terlanjur: `migrations/supabase/03_fix_sequence_ids.sql` ↔ `migrations/mysql/03_fix_sequence_ids.sql`.
- Sesuai konvensi ini, API login/profile memakai `supabaseAdmin` (service role) di sisi server, dan `admins` di-protect RLS `service_role` di Supabase.
- **⚠️ Sesi (PENTING)**: cookie `admin_session` hanya memuat **token acak 256-bit** yang disimpan di tabel `sessions` (kolom `token`, `admin_id`, `expires_at` — 7 hari). Setiap permintaan API DIVALIDASI ke DB via `getSessionAdminId` di `src/lib/apps.ts` (async, `await` wajib). Format cookie lama `base64(id:timestamp)` **TIDAK diterima** (bisa dipalsukan tanpa kata sandi). Alur: login → `createSession(adminId)` + `setSessionCookie`; logout → `destroySession` + `clearSessionCookie`. Helper ada di `src/lib/apps.ts` (bukan di route).

## Data Aplikasi (Portal Direktori Aplikasi)
- Tabel inti selain `admins`: `sessions` (sesi login token acak), `categories`, `apps`, `app_tech` (teknologi per aplikasi), `app_screenshots` (tangkapan layar per aplikasi), `settings` (key-value).
- **Screenshot memakai TABEL ANAK, bukan kolom array/JSON.** PostgreSQL punya `TEXT[]`, MySQL tidak — dan konvensi paritas menuntut alur yang sama persis di kedua DB. Jadi `app_screenshots` mengikuti pola `app_tech`: saat aplikasi disunting, seluruh barisnya diganti (`replaceScreenshots` di `src/lib/apps.ts`).
- **⚠️ Idempotensi MySQL:** MySQL 8.0 **tidak** punya `ADD COLUMN IF NOT EXISTS` maupun `CREATE UNIQUE INDEX IF NOT EXISTS` (itu MariaDB/PostgreSQL). Migrasi yang menambah kolom/indeks di file MySQL WAJIB dijaga dengan pemeriksaan `information_schema` + SQL dinamis (`PREPARE`/`EXECUTE`, no-op `DO 0`) — lihat `migrations/mysql/07_add_public_catalog_fields.sql`. Tanpa itu, migrasi gagal "Duplicate column name" saat dijalankan ulang.
- **⚠️ Jangan tambahkan `setval` untuk tabel yang dibuat KOSONG.** `setval(seq, 0, true)` melempar error "out of bounds" di PostgreSQL. Gotcha sequence di bawah hanya berlaku untuk migrasi yang memasukkan baris dengan **id eksplisit**.
- Tipe `App` (lihat `src/types/index.ts`): `status` ∈ active/inactive/maintenance/deprecated, `env` ∈ production/staging/development, `progress` 0–100, `tech` array → disimpan di relasi `app_tech`. Field katalog publik (`slug`, `isPublic`, `logoUrl`, `goLiveDate`, `contact*`, `screenshots`) sengaja **opsional** supaya data contoh `initialData.ts` dan database yang belum menjalankan migrasi 07 tetap jalan.
- **Field baru WAJIB opsional di `validateAppInput`.** Validator itu juga dipakai jalur impor (`api/admin/data`), dan berkas backup yang dibuat sebelum migrasi 07 tidak punya field baru — mewajibkannya membuat seluruh backup lama gagal diimpor.
- **Sumber data:** semua halaman (dashboard, apps, categories) fetch via `src/lib/apps.ts` (`getAllApps`/`getAllCategories`, memakai `cache()` React untuk dedupe per request). `src/data/initialData.ts` (APP_DATA) hanya **fallback** bila Supabase tidak terkonfigurasi / query gagal.
- **API apps:** `GET/POST /api/apps`, `PATCH/DELETE /api/apps/[id]`, `GET/POST /api/categories`, `PATCH/DELETE /api/categories/[name]` — semua butuh cookie `admin_session` (cek via `getSessionAdminId` di `src/lib/apps.ts`). POST membuat kategori otomatis bila nama kategori belum ada. Rename kategori (`PATCH`) otomatis mengubah nama kategori semua app (relasi via `category_id`); delete kategori membuat app-nya `Uncategorized` (FK `ON DELETE SET NULL`).
- **⚠️ Frame SSE WAJIB bernama `event: change`.** Klien (`useRealtime`) mendengarkan lewat `addEventListener('change', …)`, sedangkan frame SSE tanpa baris `event:` sampai sebagai event bernama `message`. Ketidakcocokan ini pernah membuat realtime **tidak pernah** memicu refetch sama sekali — yang bekerja hanya polling 10 detik, sehingga cacatnya tidak terlihat. Sudah diperbaiki di `src/app/api/realtime/route.ts`; jangan hapus baris `event: change\n`.
- **Realtime:** endpoint SSE `GET /api/realtime` (butuh `admin_session`) meneruskan event `postgres_changes` dari `supabaseAdmin` untuk tabel `apps`, `app_tech`, `app_screenshots`, `categories`, `activity_logs`. Klien memakai `useRealtime` (`src/hooks/useRealtime.ts`) — event memicu refetch `GET /api/apps` + `GET /api/categories` + `GET /api/technologies`, plus polling cadangan 10 detik. Agar event terkirim, tabel wajib terdaftar di publikasi `supabase_realtime` (lihat `migrations/supabase/02_enable_realtime.sql`).
- **Teknologi (TANPA tabel registri):** daftar teknologi = `SELECT DISTINCT tech FROM app_tech` (`getAllTechnologies` di `src/lib/apps.ts`). Tech baru otomatis muncul begitu dipakai oleh sebuah aplikasi. API: `GET /api/technologies`, `PATCH/DELETE /api/technologies/[name]` (butuh `admin_session`; rename/delete langsung memodifikasi relasi `app_tech`). Halaman `/technologies` = browse + tambah + rename + hapus. Teknologi yang **ditambahkan dari halaman itu disimpan di localStorage** (`custom_technologies`, helper `src/lib/customTech.ts` — pola sama seperti `custom_categories`) karena belum ada barisnya di `app_tech`; ia muncul di pilihan form aplikasi (di-merge di `AppsPage`) dan otomatis berpindah ke database begitu dipakai sebuah aplikasi.
- **Form tambah/edit aplikasi** (`AddAppModal.tsx`): kategori memakai `<select>` dari data `categories`; tech stack memakai multi-select chip dari `getAllTechnologies` + input untuk menambah nama baru (langsung ikut tersimpan ke `app_tech`).
- **Log Aktivitas** (migrasi `06_add_activity_logs.sql`): tabel `activity_logs` (audit trail) mencatat siapa (admin_username) melakukan aksi apa (create/update/delete/import/reset) pada entitas apa (app/category/technology/system). Pencatatan dilakukan di route mutasi via `logActivity` (`src/lib/apps.ts`, best-effort); sesi diambil lengkap (id+username) lewat `getSessionAdmin` (bukan hanya `getSessionAdminId`). Halaman `/logs` + API `GET /api/logs` (filter action/entityType/search + pagination + total).
- Kategori & icon/gradient di halaman Kategori: nama kategori dari DB; pengaturan visual (icon/gradient) tetap localStorage `custom_categories`.

## Katalog Publik (Tier 1 — rute tanpa login)
- **Portal ini punya DUA wajah.** Rute publik (`/`, `/katalog`, `/katalog/[slug]`, `/help`) terbuka tanpa login; sisanya (dashboard, apps, categories, technologies, logs, settings) tetap di balik sesi. Gate ada di `src/proxy.ts` dan sudah **dibalik menjadi daftar-izin** (`PUBLIC_EXACT` + `PUBLIC_PREFIXES`): yang tidak terdaftar otomatis dilempar ke `/login`. Konsekuensinya penting — **halaman admin baru otomatis terlindungi**, tapi halaman publik baru WAJIB didaftarkan manual.
- Pencocokan `/katalog` **berbasis prefiks**, bukan kecocokan persis, supaya rute gambar OG bersarang (`/katalog/<slug>/opengraph-image`) tetap terjangkau crawler — `config.matcher` hanya mengecualikan `opengraph-image.png` di root.
- **⚠️ SATU PINTU BACA PUBLIK: `src/lib/public.ts`.** Halaman publik **TIDAK BOLEH** mengimpor `getAllApps` dari `@/lib/apps`. Alasannya bukan gaya, tapi kebocoran data: `getAllApps` mengembalikan `App` lengkap termasuk `server`, `database`, `env`, `progress`, dan data itu ikut terkirim ke browser sebagai payload RSC **walau tidak dirender di layar**. `public.ts` memilih kolom secara EKSPLISIT (`PUBLIC_COLUMNS`), jadi kolom sensitif baru di tabel `apps` tidak otomatis bocor.
- Tipe `PublicApp` (`src/types/index.ts`) sengaja **tidak punya** `server`/`database`/`env`/`progress`. Menyembunyikan field di JSX mudah terlupa; menghilangkannya dari tipe membuat kebocoran gagal di `tsc`. Satu-satunya pembuat `PublicApp` adalah `toPublicApp()`.
- **Visibilitas = `apps.is_public`, penentu tunggal.** `DEFAULT FALSE` (aman secara default). Migrasi 07 mem-backfill `TRUE` hanya untuk baris lama yang `env='production' AND status IN ('active','maintenance')`, dan backfill itu dikurung di cabang "kolom baru dibuat" supaya menjalankan migrasi dua kali TIDAK menghidupkan kembali aplikasi yang sengaja disembunyikan admin. Toggle di form **tidak** menyalakan dirinya sendiri berdasarkan env/status — banyak aplikasi internal juga "produksi & aktif", jadi form hanya memberi saran.
- **Slug stabil.** `apps.slug` dibuat saat aplikasi dibuat dan **tidak ikut berubah saat nama diubah** (`updateApp` mempertahankan slug lama) — tautan yang sudah tersebar di materi sosialisasi tidak boleh mati. Admin tetap bisa mengubahnya manual. Aturan slug dasar di `src/lib/slug.ts` dibuat **sama persis** dengan backfill SQL di migrasi 07; kalau salah satu diubah, ubah keduanya. Aplikasi tanpa slug tidak muncul di katalog (query publik menyaring `slug IS NULL`) — karena itu jalur impor di `api/admin/data` juga membuat slug.
- **Cache katalog:** `getPublicApps()` dibungkus `unstable_cache` (tag `katalog`, revalidate 300s) supaya scraper tidak menembus DB. Pasangannya WAJIB: setiap route mutasi admin memanggil `revalidateKatalog()` (`src/lib/public.ts`) — sudah dipasang di route apps, categories, technologies, dan admin/data. **Menambah route mutasi baru tanpa memanggilnya = suntingan admin tidak tampil publik sampai 5 menit.** Argumen kedua `revalidateTag` di Next 16 wajib; dipakai `{ expire: 0 }` (tanpa jendela basi) agar admin langsung melihat hasil terbitannya.
- Halaman publik **sengaja tidak memakai** `export const dynamic = 'force-dynamic'` (berbeda dari halaman admin): `/katalog` dinamis karena membaca `searchParams` tapi bebannya diserap cache data, sedangkan `/` dan `/katalog/[slug]` justru butuh `revalidate = 300`. `/katalog/[slug]` **tanpa `generateStaticParams`** — build bisa jalan tanpa env Supabase dan akan memanggang slug dari data fallback.
- **Gambar:** `next/image` hanya untuk aset LOKAL (`/img/*`). Logo & screenshot aplikasi adalah URL **remote** yang diisi admin dengan host sembarang — dirender dengan `<img loading="lazy">` biasa + fallback inisial (`getInitials` di `src/lib/appMeta.ts`), karena mendaftarkan `remotePatterns` wildcard akan mengubah image optimizer menjadi proxy fetch terbuka. Setiap `<img>` semacam itu diberi komentar `eslint-disable-next-line @next/next/no-img-element` berisi alasannya.
- `src/lib/appMeta.ts` adalah satu-satunya sumber peta status (`statusStyle`, `STATUS_LABEL`, `STATUS_DOT`, `getInitials`). Sebelumnya diduplikasi di `AppsPage`, `DashboardPage`, dan inline di `DetailDrawer`.
- `src/lib/branding.ts` memegang `SITE_URL` (override lewat `NEXT_PUBLIC_SITE_URL`) yang dipakai `metadataBase`, `robots.ts`, dan `sitemap.ts` — dulu nilainya diketik ulang di tiga tempat.
- **Tidak ada tautan "Masuk Admin" di permukaan publik** — tombolnya cukup berlabel "Masuk". Ia **berubah menjadi "Dashboard"** bila admin sedang login, lewat `GET /api/session-hint`. Endpoint itu HANYA memeriksa keberadaan cookie (nol query DB, nol data dibocorkan) dan statusnya ditanyakan dari klien setelah mount — **bukan** dibaca sebagai cookie di Server Component, karena itu akan membuat `/` dan `/katalog/[slug]` dinamis dan membatalkan `revalidate = 300`. Cookie palsu hanya menghasilkan label tombol; gate sesungguhnya (`getSessionAdmin`, validasi token ke DB) tetap menolaknya — sudah diuji: `/api/apps` membalas 401.
- Dropdown profil di `Topbar` punya tautan **Beranda Publik** & **Katalog Publik** (tab baru) — sejak `/` bukan lagi redirect ke `/dashboard`, admin butuh jalan memeriksa hasil terbitannya seperti yang dilihat warga.
- **⚠️ Hero publik memakai VIDEO dua lapis** (`HeroMedia`): satu lapis blur mengisi seluruh kartu, satu lapis tajam dipotong ke jendela membulat, keduanya digerakkan SATU state `index` supaya tidak pernah memutar adegan berbeda. Ini bukan pemborosan — CSS tidak bisa membuat satu elemen tajam di satu wilayah dan blur di wilayah lain, dan empat bilah `backdrop-blur` meninggalkan jahitan di sudut karena `backdrop-filter` hanya menyampel backdrop di dalam kotak elemennya sendiri. Inset jendela, offset pembatalnya, dan garis bingkai memakai konstanta bersama (`HERO_WINDOW`, `HERO_WINDOW_OFFSET`, `HERO_RADIUS`) supaya mustahil tidak sinkron.
- **⚠️ `next/og` (`ImageResponse`) RUSAK di environment ini** — rutenya membalas 500 dan dev server mencatat "Jest worker encountered child process exceptions". Itu sebab ikon & kartu OG dibuat statis lewat `scripts/gen_static_images.py` (PIL). Halaman detail memakai `images: ['/opengraph-image.png']`. Jangan ganti ke ImageResponse tanpa memverifikasi rutenya benar-benar mengembalikan PNG.
- **Soft 404 pada `/katalog/[slug]`**: `notFound()` di respons yang sudah ter-stream mengembalikan **200**, bukan 404 — perilaku terdokumentasi Next (`404` hanya untuk respons non-stream). Next menyuntikkan `<meta name="robots" content="noindex">` sehingga tidak terindeks, dan itu mitigasi yang disarankan dokumentasinya sendiri. Sudah diverifikasi ada.
- **Setelah menjalankan migrasi, cache katalog perlu dibatalkan.** `getPublicApps()` bisa memegang hasil `[]` dari sebelum migrasi sampai 300 detik berlalu. Cara tercepat: lakukan satu mutasi apa pun di admin (memicu `revalidateKatalog()`).

## Peran & Keamanan Tier 3 (migrasi 08 — WAJIB dipatuhi)
- **ATURAN EMAS kini ditegakkan PENUH**: SETIAP route mutasi memanggil `requireRole` (`src/lib/roles.ts`). Konten (apps/categories/technologies/changelogs) butuh `admin`; reset (`DELETE /api/admin/data`) dan import (`POST /api/admin/data`) butuh `superadmin`. Route baca tetap cukup login (`viewer` boleh membaca). Dulu hanya route akun/sesi yang menegakkan — akun `viewer` bisa menghapus seluruh data lewat API. JANGAN pernah menambah route mutasi baru dengan `getSessionAdmin` saja.
- **UI bukan pengaman**: hook `useRole()` (`src/hooks/useRole.ts`, cache modul 60 dtk) hanya MENYEMBUNYIKAN tombol/menu yang pasti ditolak server (Tambah/Edit/Hapus di Apps/Categories/Technologies/Settings, menu System+Users untuk viewer). Nilai `null` = belum diketahui — jangan perlakukan sebagai viewer.
- **Ganti password mencabut sesi lain** via `revokeOtherSessions(adminId, currentToken)` — sesi peminta dipertahankan. Pola yang sama sudah dipakai penurunan peran (`revokeSessionsOfAdmin`).
- **Rate limit login**: in-memory sliding window di `src/lib/rateLimit.ts` (8 gagal/10 mnt per username+IP-hash, 30 gagal/10 mnt per IP → 429 + Retry-After; alasan baru `rate_limited` di login_logs). Counter hilang saat restart — terima konsekuensi ini, jangan tambah Redis tanpa kebutuhan nyata.
- **Import/reset anti-data-hilang**: Supabase JS tak punya transaksi dan RPC memecah paritas MySQL — maka `snapshotData()` menyimpan seluruh baris lama DI MEMORI sebelum wipe; insert gagal di tengah → `restoreSnapshot()` mengembalikan persis keadaan semula (id eksplisit dipertahankan agar `activity_logs.entity_id` tetap benar). Catatan PostgreSQL: restore id eksplisit tidak menggerakkan sequence — jalankan `migrations/*/03_fix_sequence_ids.sql` bila INSERT baru menabrak.
- **`sessions.last_seen_at`**: ditulis oleh `touchLastSeen()` di `getSessionAdminByToken`, maksimal sekali per menit per sesi (throttle memakai nilai yang ikut terbaca di query validasi — tanpa query ekstra). Tampil di halaman Sesi Aktif.
- **Changelog aplikasi** (tabel `app_changelogs`, sejak migrasi 08): tipe `AppChangelog`, lib `src/lib/changelogs.ts`, API `/api/changelogs` (+`/[id]`) — mutasi butuh `admin`. UI admin = section "Riwayat Versi" di DetailDrawer; publik = timeline di `/katalog/[slug]` via `getPublicChangelogs()` (cache tag `katalog` — ikut ter-flush `revalidateKatalog()`; entri `is_public=false` TIDAK PERNAH keluar dari lib). `entityType` log baru: `'changelog'`.
- **Pencarian log**: setiap pola ILIKE dari input pengguna WAJIB dibungkus `escapeIlike()` (validate.ts) — `%`/`_` mentah merusak hasil pencarian.
- **Unggah gambar** (`POST /api/upload`, komponen `ImageDropzone` drag & drop): **DUA DRIVER** — Supabase Storage bucket `app-media` bila env terisi (bucket dibuat otomatis saat unggahan pertama; public read; tulis via service-role), atau **disk lokal `public/uploads/apps/`** untuk deploy MySQL/Laragon (URL `/uploads/apps/...`; asumsi single-instance). Mime di-whitelist `VALID_IMAGE_MIME` (PNG/JPG/WebP/GIF — **SVG sengaja dilarang**), maks 5 MB (`LIMITS.uploadMaxBytes`), nama berkas asli tak pernah jadi path. **Tidak ada lagi jalur tempel-URL di form aplikasi** — baris screenshot hanya lahir dari unggahan.
- **Registri & GC media (migrasi 09)**: tabel `media_files` mencatat SETIAP URL gambar (driver `supabase|local|external`) + backfill seluruh URL lama sebagai `external`. Setelah `updateApp`/`deleteApp` sukses, `gcMedia()` (src/lib/media.ts) menghapus **berkas fisik** yang tidak lagi direferensikan aplikasi mana pun (dicek ulang ke DB — dua app boleh menunjuk URL sama). Aturan mutlak: URL `external` TIDAK PERNAH disentuh pembersih. Reset/import TIDAK memicu GC (berkas yatim dibiarkan — aman, hanya boros ruang); unggahan yang formnya dibatalkan tanpa simpan juga menjadi yatim (keterbatasan diketahui).

## Hidrasi React & Koeksistensi Ekstensi Browser (PENTING)
- **Aturan emas: jangan pernah baca `localStorage`/`window`/`document` saat render** (di luar `useEffect`/event handler). Server & client akan merender beda → error hidrasi + re-render penuh. Semua preferensi (tema, card view, notif read, custom categories/tech) WAJIB dibaca di `useEffect`, dipakai untuk render hanya setelah mount.
- **Jangan inisialisasi state dengan nilai non-deterministik** seperti `useState(() => Date.now())` — server & hidrasi beda beberapa ms → mismatch teks (mis. "baru saja" vs "1 menit lalu") di batas menit/jam. Pola aman: inisialisasi 0 lalu set di effect/fetch (lihat `Topbar`), ATAU tandai elemen teks-nya `suppressHydrationWarning` (lihat sel waktu di `LogsPage` — teks relatif waktu memang diizinkan beda).
- **Tema (anti-FOUC):** class `dark` di-set di `<html>` oleh inline script di `src/app/layout.tsx` (membaca `app_dark_mode` SEBELUM paint), bukan oleh React. Semua styling gelap memakai variant Tailwind `dark:` yang keyed ke `.dark` di `<html>` (lihat `@custom-variant dark` di `globals.css`) — jangan pernah menggantinya dengan class kondisional dari state (mis. `${isDark ? 'dark' : ''}` di wrapper), karena state baru berubah setelah mount → flash.
- **`suppressHydrationWarning` di `<html>`/`<body>` (`layout.tsx`):** wajib dipertahankan — ini yang membuat mutasi atribut dari luar (inline script tema, ekstensi yang menambah class/atribut sebelum hidrasi) tidak memicu error hidrasi.
- **Mount point ekstensi:** `<div id="ext-root">` di `layout.tsx` adalah satu-satunya tempat resmi ekstensi browser menyuntik node. Elemen ini statis & tak pernah di-render ulang React, jadi node yang disuntik setelah hidrasi bertahan. Ekstensi yang menyuntik ke `<main>`/list React akan merusak hidrasi (mismatch → React buang HTML SSR & re-render penuh, node ekstensi terhapus). Jika membuat fitur yang menampung node pihak ketiga, gunakan wadah di luar subtree yang re-render (jangan di dalam komponen ber-state).
- **Realtime/SSE** (`useRealtime`): polling cadangan 10 detik WAJIB dipertahankan — ekstensi/adblock bisa memblokir `fetch`/`EventSource`.
- Recharts `ResponsiveContainer` (`DashboardPage`) aman untuk SSR di v3 (render kontainer kosong sampai terukur di client); jangan downgrade/upgrade versi tanpa verifikasi hidrasi.
